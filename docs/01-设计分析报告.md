# Linear 复刻 · Study 阶段设计分析报告

> 研究方式：**Clean-room**（只观测公网可见界面、渲染结果与计算样式，不读打包 JS、不做源码逆向）
> 采集工具：Chromium CDP（`Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot` + `Runtime.evaluate` 读取 `getComputedStyle` / CSS 自定义属性 / DOM 几何）
> 采集对象：`linear.app` 首页（内含一个 1320×720 的**真实 DOM 渲染的 App 界面**，非图片）、`/features`、`/method`、`/pricing`、`/customers`
> 采集产物：`study/data/*.json`（原始 token 与 DOM 几何）、`study/shots/*.png`（1x/2x 截图与局部裁切）
> 时间：2026-11-08

---

## 0. 一句话结论

Linear 的「高级感」不来自装饰，而来自四件事：
**极窄的色阶（只有 5 个灰度层级 + 1 个品牌靛蓝）**、**12–14px 的小字号 + 510/590 的字重**、**28/32px 的紧凑行高与 8px 的圆角体系**、**100–160ms 的 ease-out 微动效**。
复刻的关键不是画得像，而是把这三组数值**当成硬约束**去写，任何一处「随手放大 2px」都会立刻变成普通后台。

## 1. 整体布局结构（实测）

首页 hero 里那个 App 窗口是真实 DOM，实测几何如下（逻辑像素）：

```
frame            1320 × 720     外层窗口（圆角裁切）
 ├ sidebar        232 × 704     左内边距 8，上 8，下 16，右 16 → 内容宽 208
 └ view          1072 × 704     窗口视图（radius 8 / 1px 内描边 .05 / 外投影 0 0 0 2px rgba(0,0,0,.2)）
    ├ panel      1070 × 702     1px 内缩，作为整个主区
    │  ├ locationBar  1070 × 44   padding 8/12，左面包屑、右分页与导航箭头
    │  ├ viewBar      1070 × 44   padding 8/12，右侧一排 28px 圆形 pill 按钮
    │  └ viewBody     1070 × 614
    │     ├ body（正文流）   661.8 宽，padding 19/16/0/16
    │     ├ propertiesColumn 286.5 宽，padding-top 8，**列内 gap 24**
    │     └ chatBox（浮层）  400 × 520，绝对定位，位于正文右侧、覆盖属性栏之上
```

要点（这些是「像不像」的第一层）：

1. **左侧栏 232px 是固定值**，折叠后为 0；不是可拖拽的 240/280。
2. **顶栏是两条 44px 的横带**，不是一条 56px 的 navbar：
   - `locationBar` = 面包屑 + 上下条导航（`1 / 84`），高 44，内边距 `8px 12px`；
   - `viewBar` = 视图级动作（筛选 / 排序 / 显示 / 分组），同样 44px 高。
   两条带**都不画底线**，靠背景层级差分开，视觉上像一整块。
3. **正文列 ≈ 662px + 属性列 286px + 56px 间隙**，正文列不是满宽拉伸，而是被约束在中间偏左；这是 Linear 读起来「安静」的根本原因。
4. 主区圆角 8px，外加 1px 的内描边（`rgba(255,255,255,.05)`）与 2px 的黑色外扩投影——**它像一块玻璃贴在页面上**，而不是一个 div。

- 主按钮/新建议题：`bg .02 + border #24282C`
- 弹层：`bg #161718 + border .12 + shadow 0 2px 32px rgba(0,0,0,.25)`

## 3. 字体与字号体系（实测）

- 字体栈实测：`"Inter Variable", "SF Pro Display", -apple-system, BlinkMacSystemFont, "Segoe UI", ...`
- 等宽：`"Berkeley Mono", ui-monospace, "SF Mono", Menlo, monospace`（仅代码块/行内 code）
- **字重不是 400/500/700，而是 400 / 510 / 590 / 680**（`--font-weight-medium:510`、`semibold:590`）。Inter Variable 的 510/590 是 Linear 字感偏「紧致」的秘密：

| Token | 字号 | 行高 | 字距 |
|---|---|---|---|
| `--text-micro` | 12px | 1.4 | 0 |
| `--text-mini` | 13px | 1.5 | `-.01em` |
| `--text-small` | 14px | 21/14 | `-.013em` |
| `--text-regular` | 15px | 1.6 | `-.011em` |
| `--title-1` | 17px | 1.4 | `-.012em` |
| `--title-2` | 20px | 1.33 | `-.012em` |
| `--title-3` | 24px | 1.33 | `-.012em` |
| `--title-6` | 48px | 1 | `-.022em` |

实测具体用例：
- 侧栏导航项：**13px / 510**
- 面包屑编号与标题：**12px / 510**，行高 14
- 议题标题（App 内）：20px / 590（营销 frame 缩过；真实产品为 24px / 590）
- 正文描述：14–15px / 400，行高 1.5
- 评论正文：13px / 400 `#8A8F98`，作者 13px / 510 `#D0D6E0`
- 活动流：12px，人名同字号 510
- 属性栏标签：12px（节标题 12px，行内值 12px）
- 行内 code：12px + `radius 4 + bg .05 + border .08 + padding 1px 6px`

## 4. 间距 / 圆角 / 阴影 / 动效

**圆角**（实测频次）：`4 / 6 / 8 / 9 / 12 / 16 / 9999`。语义固定：

| 半径 | 用途 |
|---|---|
| 4px | code chip、model tag、小方块 |
| 6px | 菜单项、小按钮 |
| 8px | 侧栏导航项、输入框、主窗口 |
| 9px | 议题卡片、评论区大卡 |
| 12px | 浮层面板（AI 面板）、对话框 |
| 16px | label 胶囊 |
| 9999 | 圆形图标按钮（28×28）、split pill |

**间距节奏**：4 / 6 / 8 / 12 / 16 / 24。列表行 28（侧栏）/ 32–36（列表）/ 24（属性行）。

**阴影只有三档**（其余全部 `none`，这是他们克制的地方）：
```
hairline  inset 0 0 0 1px rgba(255,255,255,.05)
overlay   0 2px 32px rgba(0,0,0,.25)       + 1px rgba(255,255,255,.12)
frame     0 0 0 2px rgba(0,0,0,.2)         + 1px rgba(255,255,255,.05)
```

**动效**（实测 `transition` 属性直方图）：
- 主力曲线 `cubic-bezier(.25,.46,.45,.94)`（= `--ease-out-quad`）
- 时长 **0.1s**（文字/颜色，最高频 187 处）→ **0.16s**（背景/边界）→ **0.25s**（跨组件）
- 过渡属性白名单：`color / background / border-color / box-shadow / opacity / filter / transform`
- **没有任何弹性回弹**：没有 `spring`、没有 overshoot；`linear` 只用于进度条
- 滚动条：宽 6px，`#ffffff1a`，hover `#ffffff33`

**层级（z-index，实测 `:root`）**：
`header 100 / overlay 500 / popover 600 / command-menu 650 / dialog-overlay 699 / dialog 700 / toasts 800 / tooltip 1100`
→ 复刻时必须照抄这个顺序，否则 Command Menu 会被 popover 盖住。

## 6. 交互与动效特点（可执行的规则）

1. **速度感来自「没有过渡的过渡」**：文字/图标颜色 100ms；背景与边框 160ms；唯一超过 200ms 的是浮层进出场（200–240ms）与侧栏折叠（240ms）。
2. **hover 只改背景，不改尺寸**；从不做 `translateY(-1px)` 之类的位移（那会把 Linear 变成 shadcn demo）。
3. **focus 用 1px 环 + 2px offset**，不加粗边框，不改变布局。
4. **选中态用「白色 4% 叠加 + 左侧无指示条」**；多选时才出现复选框（16px，圆角 4）。
5. **抽屉/浮层入场**：`opacity 0→1` + `translateY(4px)→0` + `scale .985→1`，240ms `--ease-out-quad`；出场 160ms，反向且不做 scale。
6. **列表换视图（List ⇄ Board）用 crossfade + 80ms 延迟**，不做位移滑动。
7. **拖拽**：抓起时卡片 `scale 1.02 + rotate 1.5deg + shadow 0 12px 32px rgba(0,0,0,.5)`，落点用 2px 靛蓝线提示；松手 160ms 归位，无回弹。

## 7. 快捷键体系（复刻目标）

Linear 的键盘优先不是「有快捷键」，而是「**任何操作都能不离开键盘、且有反馈**」。

| 键 | 行为 | 反馈要求 |
|---|---|---|
| `⌘K` / `Ctrl K` | Command Menu | 浮层 + 输入框自动聚焦 |
| `/` | 同上（聚焦搜索） | — |
| `C` | 新建议题 | 就地插入一行可编辑行，不跳页 |
| `G` → `I` / `B` / `P` | 跳到 Inbox / Board / Projects | 顶部短暂 toast「Go to …」 |
| `J` / `K` | 下 / 上一条 | 选中行滚动进视口，焦点环跟随 |
| `X` | 切换当前行选中（多选） | 复选框淡入 |
| `Shift + ↑/↓` | 范围多选 | 同上 |
| `Enter` | 打开选中议题 | 抽屉滑入 |
| `Esc` | 逐层关闭（下拉 → 抽屉 → 选中清除） | 每层独立 |
| `⌘Enter` | 保存编辑 | 标题栏右侧短暂出现「Saved」 |
| `⌘\` | 折叠 / 展开侧栏 | 宽度动画 240ms |
| `?` | 快捷键面板 | 居中浮层 |
| `⌘B` `⌘I` `⌘U` | 粗体 / 斜体 / 下划线（描述编辑器） | 选区变化即刻反映 |

## 10. 结论

Linear 的界面在数值上非常「窄」：一种字体、五级灰、一个强调色、四档圆角、三档阴影、两个时长档位。
**复刻策略因此定为「先锁死数值，再谈功能」**——Design System 先行，任何组件只能从 token 里取值，不允许出现 `bg-[#1a1a1a]` 这类一次性硬编码。这样即使后续不断加功能，整体气质也不会漂移。
