## 3. 目前像不像（主观）

**像。** 打开第一眼的关键判据是：暗色底足够黑（#08090A 而不是 #121212）、字号足够小（13px 不是 16px）、行高足够紧（36px）、强调色只有一种、动效没有弹跳。这五条都落到了数值上，所以整体气质是对的。

**还差的几口气**（按影响排序）：

1. **侧栏顶部与底部的「信息余量」**：Linear 侧栏底部还有 workspace 切换、邀请、更新提示等，目前只有用户行，显得略空。
2. **行 hover 的微交互**：Linear 在 hover 时会在行尾淡入一个「⋯」与快捷键提示；目前只有复选框淡入。
3. **详情页右上的动作组**（attachment / branch / merge / more 四个 28px pill）：目前只有 star + more。
4. **看板拖拽的侧向自动滚动**较生硬（每次 14px），没有缓动。
5. **描述编辑器的行内格式化**只做了 Markdown 包裹，没有真正的选区样式（粗体预览需要保存后才渲染）。
6. **动效细节**：视图在 list ⇄ board 之间是直接切换，没有 80ms 的交叉淡入。

## 7. 移动端断点（本轮新增）

断点口径：`lg = 1024px` 为侧栏分界，`sm = 640px` 为信息密度分界；验收视口 390×844（@2x）。

| 区域 | < lg / < sm 行为 | 实测 |
|---|---|---|
| 侧栏 | 变成覆盖式抽屉：264px、`translateX` 滑入、遮罩 55% + 1px 模糊；路由变化自动收起；`⌘\` 改为开抽屉；关闭时 `inert` + `aria-hidden` | 关闭 `translate(-266.6px)`、打开 `0`，宽度 264 |
| 顶栏 | 左侧换汉堡；`< lg` 收起面包屑尾段（`/ Issues`）、issues 计数、排序与显示菜单；`< sm` 时 `All/Active/Backlog` 移到第二行（34px 高，可横滑） | 768 下无溢出（`scrollWidth = 768`），汉堡 + 团队名 + tabs + 视图切换 + 筛选 + 新建 全部落位；390 下 `scrollWidth = 390` |
| 列表行 | 行高 38（触控），隐藏 ID / 优先级 / 指派 / 日期，保留状态 + 标题；`⋯` 常显 | 行高 38，`⋯` `opacity: 1` |
| 看板 | 列宽 `84vw`（上限 320）+ `snap-x` 强制吸附；高度按 78 / 112px 顶栏重算；触屏拖动让位给横向滚动，改状态走卡片状态字形 | 列宽 320、看板高 766（844 − 78） |
| 详情抽屉 | 全屏（`left: 0`）；标题 28px；属性栏折叠为标题下的横向芯片行（状态/优先级/指派/标签/项目/Cycle/截止/估点，复用同一批弹层）；头部只留状态、Key、收藏、`⋯`、关闭 | 抽屉左边界 0，右侧属性栏 `display: none`，芯片可横滑 |
| 批量条 | 外层负责固定与居中（避免 framer 的内联 transform 顶掉 `-translate-x-1/2`），内层可横滑，`< sm` 只显示图标 | 1440 下条居中（475–965，中心 720） |

## 8. 本轮顺手修掉的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 批量操作条不居中 | framer-motion 给元素写内联 `transform`，把 Tailwind 的 `-translate-x-1/2` 顶掉了，导致条从 50% 处向右排 | 外层 div 负责 fixed + `justify-center`，motion 只动内层；实测中心 = 720 |
| 顶栏控件挤爆（768 宽下 issues 计数换行、+ 被推出屏） | 桌面控件原样保留 | `< lg` 先隐藏计数与排序/显示菜单；`< sm` 再把 tabs 移到第二行，筛选收成图标 + 数字 |
| 看板高度在手机上算错 | 顶栏在手机上多了一行 tabs（44 + 34） | 改为按断点算 78 / 112px，不再用内联 style |
| Roadmap 手机端项目名只剩 2 个字 | 标签列固定 132px + 显示百分比 | 标签列 156px，`< sm` 隐藏百分比 |
| 亮色下 Toggle 像被切掉 | 白色圆钮贴在白色卡片上，边界消失 | 圆钮加 `0 1px 2px rgba(0,0,0,.32)` 阴影 |
| 关闭的移动抽屉仍可 Tab 进入 | 只做了位移 | 关闭时加 `inert` + `aria-hidden` |

| 项 | 做法 | 验收 |

## 10. 第五轮：命令面板与拖拽手感（已完成）

| 项 | 做法 | 验收 |
|---|---|---|
| 命令面板「最近使用」 | 新增 `lib/recent.ts`：localStorage 存 6 条 + 自定义事件即时同步；把面板条目重构成一个 `catalog`（导航 / 动作 / 全部议题 / 全部项目一次构建），区块只是它的切片，Recent 段按 id 反查，刷新后仍然有效 | 空查询首屏为 Actions / Recently updated / Projects / Navigation；执行 `Go to Inbox` 后顶部出现 `Recent / Go to Inbox`，刷新后仍在；搜索 `sync` 命中 Issues + Projects，`↵` 打开首条 |
| 面板统一关闭 | 原先只有动作类条目自己调 `close()`，导航/项目条目点完面板还开着；现在 `runItem()` 记录最近使用后统一关闭 | 点 `Go to Inbox` → 面板关闭并跳到 `/inbox`；`⌘K` 再开即可看到 Recent |
| 拖拽手感 | 触屏长按起拖时 `navigator.vibrate(8)`；边缘自动滚动从固定 7px/帧 改成 `6 + 惯性增益`（每帧 +0.4，上限 12），停手即回零 | 拖拽仍正常落列（Todo 6 → In Progress 7）；贴边拖动速度平滑上升，不再匀速爬行 |

**左边缘右滑打开抽屉：未采用。** 实测从 x≈8px 起手会被浏览器/系统的返回手势抢占 —— CDP 合成触摸里 `touchend` 直接把页面带回 `about:blank`；Android Chrome 与 iOS Safari 的边缘区都归系统，网页拿不到这段手势。因此保留汉堡与 `⌘\` 两个入口，只保留抽屉内的左滑关闭。
