# 部署

服务器上跑的是一个 Next.js 应用 + 一个 `fs` 数据目录。**有账号体系**：第一个注册的账号是工作区所有者，之后的人用邀请码加入（可选）。

## 1. 构建与启动

```bash
npm ci
npm run build
npm start                      # next start -p 4321
# 想限制注册，加一个邀请码
SIGNUP_CODE='team-only-2026' npm start
```

- Node 20+。构建不需要网络（字体本地自托管）。
- 端口写在 `package.json` 的 `start` 脚本里（默认 4321）。
- 建议放在 Nginx / Caddy 后面，反代到 4321；`/api/agent/*` 是流式的，记得关掉响应缓冲：

```nginx
location / {
  proxy_pass http://127.0.0.1:4321;
  proxy_http_version 1.1;
  proxy_buffering off;          # 智能体的 SSE 需要
  proxy_read_timeout 300s;
}
```

## 2. 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `LAB_DATA_DIR` | `<项目>/.data` | 数据目录（桌面版指向用户 AppData） |
| `SIGNUP_CODE` | 空 | 设置后，注册需要邀请码；留空则任何人都能注册 |
| `WORKSPACE_PASSWORD` | 空 | 旧版的共享密码，现在**等同于 `SIGNUP_CODE`**（兼容用，新部署请用 SIGNUP_CODE） |
| `WORKSPACE_MODE` | `shared` | `shared`=所有人共享一份工作区；`personal`=**每个账号一份独立数据** |
| `AUTH_DISABLED` | 未设 | `1` 时跳过登录，用本地单用户（只适合本机/演示） |
| `AGENT_ALLOWED_HOSTS` | 空 | 逗号分隔的模型接口白名单，公开部署建议设置 |
| `AETHER_SCHEDULER` | 开 | `0` 关闭服务端定时工作流调度 |
| `NEXT_PUBLIC_AETHER_BROWSER_SCHEDULER` | 关 | `1` 启用浏览器内调度器（仅当服务端调度被关闭时使用；两者同时开会重复执行） |
| `AETHER_UPDATE_URL` | 空 | 桌面版更新清单目录（见 `06-桌面应用.md`） |
| `LOCAL_USER_NAME` | `本地用户` | `AUTH_DISABLED=1` 时显示的名字 |

## 3. 数据存在哪里

```
.data/
  secret.key            实例密钥（加密模型 key、签发用）；不要进版本库
  users.json            账号（只有 scrypt 哈希，没有明文密码）
  sessions.json         会话令牌 → 账号（httpOnly Cookie，30 天）
  workspace.json        共享工作区快照
  workspaces/<账号>.json  personal 模式下每个账号一份
  prefs/<账号>.json      主题 / 语言 / 侧栏 / 列显示 / 收件箱已读
  agent/<账号>.json      模型配置 + AES-GCM 加密后的 key
```

行为细节：

- 首屏先渲染浏览器缓存 → 再拉服务器快照；服务器有内容时以服务器为准。
- 服务器返回 `updatedAt`；客户端写入带 `baseVersion`，**版本对不上时服务端回 409**，客户端改为拉取最新版本，不再互相覆盖。
- 任何改动 500ms 防抖后写本地 + `PUT /api/workspace`；写入是串行的（服务端按文件加锁）。
- 切回标签页（focus / visibilitychange）重新拉一次，另一台设备的改动会进来。
- 设置 → 偏好 →「工作区存储」会显示当前是「服务器」还是「本浏览器」（服务器不可达时）。
- 「重置工作区」清空当前账号可见的那份快照。

## 4. 账号与权限

- 第一个注册的人是 `owner`；owner 可以在**设置 → 成员**里移除其他人，其他人只能改自己的资料。
- 权限模型是「共享工作区」：所有账号读写同一份议题数据（和 Linear 的团队工作区一致）；个人化的只有偏好、收件箱已读、模型配置。
- 想要**每人一份数据**：`WORKSPACE_MODE=personal`，每个账号读写 `workspaces/<账号>.json`，彼此不可见。
- 忘记密码：删掉 `.data/sessions.json` 里对应用户的行不会重置密码；直接编辑 `users.json` 把该用户删掉，让它重新注册（会丢失该账号的偏好与模型配置）。
- Cookie 是 `lab_session`，httpOnly + SameSite=Lax，HTTPS 下自动加 `Secure`。

## 5. 智能体代理的安全边界

浏览器不直连模型：请求走 `POST /api/agent/chat`，服务端按会话账号取出解密后的 key 再转发。两层默认防护：

1. 只允许 `http(s)`，挡掉 `169.254.*`、`::1`、`metadata.google.internal`、`10.0.0.0`。
2. **公开部署时加白名单**：

```bash
AGENT_ALLOWED_HOSTS=api.openai.com,api.deepseek.com,open.bigmodel.cn npm start
```

没在白名单里的 host 直接 400。仓库里没有任何模型密钥。

## 6. 部署后自检

```bash
curl -s http://127.0.0.1:4321/api/auth                 # {"mode":"accounts","authenticated":false,"needsSetup":true,...}
curl -s -X POST http://127.0.0.1:4321/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"name":"You","email":"you@example.com","password":"at-least-8"}' -c /tmp/lab.cookie
curl -s -b /tmp/lab.cookie http://127.0.0.1:4321/api/workspace | head -c 200
```

页面侧：注册 → 建一条议题 → 刷新仍在 → 换浏览器登录同一账号，数据与偏好都在；设置 → Agents 保存 key 后刷新，`hasKey` 仍为真而输入框是空的（**密钥不回传浏览器**）。

## 7. 备份、升级与回滚

- 服务器侧：备份 `.data/` 整个目录（`workspace.json` + `users.json` 缺一不可）；恢复时整体放回。
- 用户侧：设置 → 偏好 →「备份」可导出/导入整份工作区 JSON（议题、标签、项目、周期、通知），不含账号。
- 数据版本键带 `:v1`；改结构时换 `STORAGE_KEY` 并写迁移。
- 静态资源 `npm run build` 覆盖即可，`.data/` 不受影响。
