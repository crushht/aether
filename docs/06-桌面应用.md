# 桌面应用（Electron）
同一个 Web 应用，外面套一层 Electron 外壳：无边框窗口、原生窗口按钮、独立数据目录、单实例、窗口大小记忆。**没有第二套前端代码**——桌面版加载的就是这个 Next 应用。

## 目录

```
desktop/
  main.mjs         主进程：起内置服务 → 等就绪 → 开窗口；菜单、外链、窗口状态
  preload.cjs      只暴露 { platform, versions } 并把 <html data-desktop="1"> 标上
scripts/
  run-electron.mjs  启动器（会清掉 ELECTRON_RUN_AS_NODE）
  desktop-dev.mjs   同时起 next dev 与 Electron
  build-desktop.mjs 打安装包：next build → 拷贝 standalone → electron-builder
  make-icon.mjs     生成 build/icon.png 与 build/icon.ico（不依赖任何图像库）
electron-builder.yml 打包配置（NSIS 安装包 + 免安装 portable）
desktop/update.cjs   更新清单解析（版本比较、URL 校验；纯 Node，可单测）
build/icon.*         应用图标
```

## 开发

```bash
npm run desktop:dev     # 一个命令：next dev(:4321) + Electron 窗口
# 或者分开跑
npm run dev
npm run desktop         # 需要 4321 已有服务
```

Electron 用独立的浏览器配置目录，所以桌面版的登录态和浏览器里的互不影响。

## 打包

```bash
npm run icon        # 只在改图标时需要
npm run dist:dir    # 快速验证：只产出未压缩的 dist/win-unpacked
npm run dist        # 正式：dist/Linear Lab-0.2.0-x64.exe（安装包）+ portable
```

打包做的事情：
1. `next build`，产物里带 `output: 'standalone'` 的自包含服务端（`.next/standalone/server.js`）。
2. 把 `.next/static` 与 `public/` 拷进 standalone（Next 不会自己拷）。
3. `electron-builder` 把 standalone 作为 `extraResources/server` 打进安装包。

运行时的进程模型：

```
Linear Lab.exe
 └─ (renderer) Next 页面
 └─ (child) server.js  —— 用 ELECTRON_RUN_AS_NODE=1 复用 Electron 自带的 Node，
                          不需要用户机器上装 Node
```

启动顺序：挑一个空闲端口 → 起 server.js（`LAB_DATA_DIR` 指到用户目录）→ 轮询 `/api/auth` → 就绪后 `loadURL`。服务起不来会弹错误框并给出日志路径。

## 数据位置

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\Linear Lab\data\` |
| macOS | `~/Library/Application Support/Linear Lab/data/` |
| Linux | `~/.config/Linear Lab/data/` |

里面就是 `docs/05-部署.md` 描述的那套文件（`users.json`、`workspace.json`、`prefs/`、`agent/`）。窗口大小记在 `window-state.json`，服务日志在 `server.log`（菜单 Help → Open data folder 可直接打开）。

## 窗口与菜单

- 无边框 + `titleBarOverlay`：Windows 上右上角是系统的最小化/最大化/关闭，颜色跟随应用。
- 顶栏自己就是拖拽区（`[data-desktop='1'] .window-drag`），里面的按钮/输入框自动退出拖拽区；右侧留 140px 给窗口按钮。
- 菜单：File（新建议题 `⌘N`）/ Edit / View（重载、缩放、全屏、开发者工具）/ Help（快捷键 `⌘/`、打开数据目录）。
- 站外链接一律用系统浏览器打开；单实例锁：再次启动会聚焦已有窗口。

## 已知边界

- 只测过 Windows x64 构建；`electron-builder.yml` 里 macOS/Linux 目标是照抄默认值，未实测。
- 有静态源更新检查，但没有自动下载/安装（见下文），也没有代码签名。
- 桌面版仍然需要一个能跑 Node 的服务进程（内置），不是纯静态站点。

## 更新检查

桌面版支持静态发布源的更新检查，但不静默安装：

1. 把 `latest.json` 放到任意静态目录：

   ```json
   { "version": "0.4.0", "url": "https://example.com/Aether-0.4.0-x64.exe", "notes": "本次更新说明" }
   ```

2. 启动桌面版前设置 `AETHER_UPDATE_URL` 指向该目录（不带末尾斜杠）。
3. 启动 10 秒后静默检查，最多一天一次；Help → Check for updates… 可手动检查。
4. 有新版本时弹窗展示版本与说明，按钮只打开下载链接，不自动替换二进制。

版本比较与清单校验在 `desktop/update.cjs`，`npm run test` 覆盖：非 http(s) 链接、缺少版本/URL、旧版本都会被拒绝。

**自动下载安装与代码签名尚未实现**：需要发布源、`electron-updater` 以及 Windows/macOS 签名证书；签名是发布决策，不是应用内可替代的能力。
