# Aether · 浅色设计诊断与质感提升记录

> 任务书 3 的第一阶段产物：先诊断，再重建设计系统，最后逐页重做。
> 参考来源：`https://linear.app/login` 的公开样式（2026-11-13 抓取），以及 Vercel / Resend /
> Arc / Cal.com / Notion 等产品公开界面中可复用的浅色设计模式。本文只记录观察与设计决策，
> 不含任何参考产品的源码或私有资源。

---

## 1. 参考观察：Linear 浅色模式实测到的值

从 `linear.app/login` 的公开样式表读到（原样引用，作为设计基线）：

| 用途 | Linear 实际值 | 说明 |
|---|---|---|
| 画布 / 侧栏 | `#EFEFF0` | 侧栏与页面底色，不是白色 |
| 内容区 | `#F9F9FA` | 比画布亮一档，靠明度差分层 |
| 描边 | `#E2E2E2` | 实色细线，不用半透明叠层 |
| 主文字 | `#23252A` | 不是纯黑；纯黑在浅色下会「发硬」 |
| 次文字 | `#5B5B5D` | 用于说明、meta |
| 弱文字 | `#B0B5C0` | 仅用于加载态等非关键信息 |
| 主按钮 | `#6D78D5`（hover `#6C78E6`） | hover 变亮，不是变深 |
| 控制圆角 | `4px`；浮层 `12px` | 小控件克制，容器才圆 |
| 按钮高度 | `32px`（登录页主按钮 32–40） | 密度高但不挤 |
| 阴影 | `0 3px 6px -2px rgba(0,0,0,.02), 0 1px 1px rgba(0,0,0,.043)` | 极低透明度、双层 |
| 字体 | Inter Variable，基础 12px / 500 | 字重是质感的一半 |

**结论**：浅色高级感来自「三段明度（画布 → 内容 → 浮层）+ 实色描边 + 低透明度双层阴影 +
非纯黑文字」。不是靠更多留白或更大圆角。

## 2. 改前诊断（具体到页面）

### 2.1 全局 Design Token

| 问题 | 实测/现象 | 影响 |
|---|---|---|
| 画布与内容都是白/近白 | `--bg-base #F7F8F8`、`--bg-panel #FFFFFF` | 侧栏、主区、卡片糊成一片，缺层次 |
| 描边用半透明 | `--line: rgba(0,0,0,.12)` 叠在近白上约 `#E0E0E0`，但叠在 hover 上会变浑 | 分组线不稳定，「脏」 |
| 主文字纯黑 | `--text-1 #0D0E10` | 浅色下对比过硬，长时间阅读累 |
| 辅助文字太浅 | `--text-4 #8B919B` | 12px meta 对比不足，显得廉价 |
| 阴影为暗色设计 | `shadow-menu: 0 8px 28px rgba(0,0,0,.45)` | 浅色下菜单像贴了一块黑雾 |
| hover 变深 | accent hover `#4F5AC2` | 与 Linear「hover 变亮」相反 |

### 2.2 登录 / 注册页（任务书重点）

- 单栏居中表单：没有品牌叙事，第一眼只是「一个表单」。
- 背景只有一层很淡的径向渐变，白底 + 白卡片 → 发白。
- 没有产品预览，用户不知道这是个什么工具。
- 品牌仍写 `Linear Lab`，与产品定位（Aether）冲突。
- 输入框 44px、按钮 44px 本身没问题，但标签、说明、错误条的层级不清晰。

### 2.3 ⌘J Agent 工作台

- 遮罩 `rgba(0,0,0,.5)`：浅色下像「黑屏」，与克制的产品气质相反。
- 面板纯白、无阴影层次；会话列表没有搜索、重命名、置顶。
- 没有「当前用的是哪个 provider / 哪个模型」，也没有上下文占用。
- 不支持附件、网页、图片；无法把回答沉淀成 Issue 或知识。
- 未配置模型时只有一行英文报错，缺少可操作引导。

### 2.4 设置页 / Agents

- 只有一个 provider 的四个字段，无法添加多个端点，无法按场景分模型。
- Key 保存后没有「已存 / 提示串」，错误只有一个笼统字符串。
- 没有记忆管理、没有人设与知识/工作流入口。
- 空状态缺失：空白表单直接铺在页面上。

### 2.5 知识库 / 工作流

- 不存在。任务书 2 的 P2 两项完全没有落点。

### 2.6 一致性

- 侧栏品牌 `Linear`、顶栏面包屑 `Linear`、桌面壳 `Linear Lab`、`package` 名 `linear-lab`：
  同一条产品线上出现四个名字。
- `/knowledge`、`/workflows` 没有面包屑名称，落到 `Issues`。
- 图标、术语（智能体 / Agent / 助手）混用。

## 4. 页面重做

### 4.1 登录 / 注册页

- 两栏：左侧品牌叙事（标题、三点能力、产品缩略预览、底部 BYOM 说明），右侧纯白表单。
- 缩略预览用真实 token 画的「mini Aether」：侧栏、议题行、Agent 审批卡。不依赖截图，深浅色都成立。
- 表单：标签 12.5/510、输入 42px、focus 三层（inset 描边 + 3px ring）、主按钮 42px。
- 错误：红色 9% 底 + 20% 描边 + 图标，不再是一行裸文字。
- 品牌统一为 Aether，新标志是「轨道 + 核心」，16px 下仍可辨认。

### 4.2 ⌘J Agent 工作台

- 遮罩改为 `rgba(24,25,27,.34)` + `blur(3px)`；面板 14px 圆角、双层阴影。
- 左栏：搜索、置顶、双击重命名、删除、模型状态 chip。
- 头部：会话标题 + 上下文占用条 + provider/model chip + 导出 Markdown / 重试 / 清空。
- 消息：用户消息右侧浅底气泡（带附件缩略），回答按「文档」排版，hover 出现
  复制 / 建 Issue / 存知识。
- 输入：白色浮起卡片、附件（文件 / 图片）、网页读取、模型与 token 元信息。
- 空状态：一句「接下来做什么？」+ 三张建议卡 + ⌘J 提示；未配置时给设置入口。

### 4.3 Agents 设置页

- 多 Provider 卡片列表（key 状态、base URL、默认模型、上下文长度、编辑）。
- 内联编辑表单：预设 chips、名称、Base URL、Key（只写不读，显示 hint）、温度、步数、上下文。
- 「按场景指定模型」四行：会话 / 议题 / 工作流 / 知识库，各自 provider + model。
- 人设与指令：persona 在系统提示最前，instructions 作为团队规则；审批与记忆开关。
- 记忆列表：可加、可删、可清空；显示 kind 与时间。
- 知识库 / 工作流入口卡。

### 4.4 知识库 `/knowledge`

- 列表 / 搜索 / 条目计数；空状态带解释与首个入口。
- 新建：笔记或网页（服务端抓取正文，拒绝内网地址）。
- 详情抽屉：标题、来源、字符数、标签、Markdown 正文；可编辑、可删除。

### 4.5 工作流 `/workflows`

- 列表卡：名称、触发方式、启用状态、上次运行、运行按钮、暂停、编辑、删除、历史。
- 编辑器：指令、provider/model、触发（手动 / 每天 / 每周 / 每 N 分钟）、
  允许写议题、报告转 Issue、启用。
- 运行历史折叠显示状态、步数、Issue 编号与摘要。

### 4.6 一致性与品牌

- 侧栏、顶栏面包屑、登录页、桌面壳、安装包统一 `Aether`。
- `/knowledge`、`/workflows` 进入面包屑与命令面板（⌘K）。
- 新增 `Agent` 相关中文词条 160+ 条，未翻译键才回退英文。

## 7. 真实模型联调（2026-11-13）

界面之外，这一轮把 BYOM 链路接到了真实模型上：本机网关 `http://127.0.0.1:8788/v1`，
模型 `deepseek-v4.1-flash`（1M 上下文，支持 tools / vision）。

### 7.1 链路结果

| 场景 | 结果 |
|---|---|
| `POST /api/agent/models` 测试连接 | 200 · 21 个模型 · 14ms |
| 普通流式对话 | SSE 正常，逐字返回，usage 汇总 |
| `create_issue` + 审批 | 模型主动调用 → 审批卡显示「优先级 高」→ 应用改动 → ENG-1 落库 → `get_issue` 复核 |
| 多轮续聊 | 第二条指令沿用上文，`update_issue` 把 ENG-1 改为进行中，回答提到「原状态 todo」 |
| `remember` | 审批后写入账号记忆，下一轮注入系统提示 |
| `search_knowledge` + `read_knowledge` | 命中「Aether 发布节奏」，回答引用了周期冻结规则 |
| Workflow 运行 | 3 步工具调用，生成两段式报告，运行历史 `ok`，报告自动建成 ENG-2 |
| 上游错误 | Key 的模型限制（400）原样透传为可读中文，UI 不吞错 |

### 7.2 联调中发现并修掉的问题

- 首次添加 Provider 时场景路由没有自动绑定（自动绑定被写在 `patch.routes` 分支内）→ 移到路由合并之后。
- 头部按钮被长标题挤压，「清空」竖排换行 → 操作区 `shrink-0 whitespace-nowrap`。
- `Thinking…` / `Waiting for your approval` / `Stopped` 三条状态文案是英文硬编码 → 走 i18n。
- 工具日志摘要全英文（`Created ENG-1`、`status → in_progress`）→ summary 中文化，状态键在渲染层映射为中文标签。
- 工作流完成 toast 英文 → i18n。
- 上下文占用 1209 tokens 显示 0% → 小于 1% 显示 `<1%`。
- 模型会在报告里直接贴 `in_progress` / `high` → 系统提示与工作流提示增加「面向人的文字用自然语言表达状态与优先级」。
- 回答下的「复制 / 创建议题 / 存入知识库」只在 hover 出现 → 改为常显 60% 透明，hover 变实。

## 9. 服务端调度（2026-11-13）

工作流不再依赖「有人打开应用」。

### 9.1 结构

```
app/layout.tsx              server layout 顶层启动（NEXT_RUNTIME=nodejs、非 build 阶段）
  └─ lib/server/scheduler.ts  每 60 秒扫描 .data/aether/*.json
       └─ lib/server/agent-run.ts
            ├─ resolveTarget(account, 'workflow')   复用 Provider 与加密 Key
            ├─ 服务端工具：list/get issues · projects · cycles · knowledge
            │              create_issue / add_comment（仅 allowWrites）
            ├─ 非流式 chat/completions + tool loop（maxSteps 上限）
            └─ 写回 aether：run 记录 + lastRunAt；报告可按设置建成 Issue
```

> 最初放在 `instrumentation.ts`，但 Next 15 dev 会为该入口编译多个 runtime，
> 把 `lib/server/*` 的 `node:crypto` 拖进非 Node bundle，页面直接 500。改到 server
> layout 顶层（`process.env.NEXT_RUNTIME === 'nodejs'` 且非 build 阶段）后，dev 与 build 都正常。

- 认领：内存 `Set` 防止同一次 tick 重入；`.data/scheduler.lock` 是 75 秒租约，
  多实例只有一个节点拿到窗口；`lastRunAt` 是持久守卫。
- 关闭：`AETHER_SCHEDULER=0`；`NEXT_PHASE=phase-production-build` 时不会启动。
- 失败：上游错误写进 run 的 `error` 与 `summary`，`lastRunAt` 仍然推进，不会形成重试风暴。

### 9.2 验证（真实网关）

把「周期体检」改为 `daily`、清空 `lastRunAt` 后启动 dev（**浏览器从未打开**）：

- 8 秒首轮扫描触发，run `status=ok`，摘要真实生成（读取了进行中议题、项目、周期与知识库）；
- `create_issue` 生效，工作区出现 `ENG-1 [周期体检] …`；
- run 写回 `aether/local.json`，`lastRunAt` 更新；
- 清理后 `trigger` 恢复 `manual`、工作区还原为空快照；
- `npm run build` 不受 instrumentation 影响（build 阶段不启动调度器）。

### 9.3 已知边界

- 服务端工具是交互式 Agent 工具的子集（没有 bulk_update / 关系 / 周期写入）。
- 登录页、列表等客户端页面不参与调度，账号配置变化在下一轮扫描生效。
- 租约是文件级的，适合单机多进程；跨主机共享目录需要换成数据库或队列。
- 服务端工具已补齐 `bulk_update`（按 keys 批量改状态/优先级）与 `set_cycle`（按 id/编号/名称归入周期，
  `none` 移出）；实测一次调度把 ENG-1/ENG-2 改为进行中、ENG-1 归入 Sprint 1。
- 启动时机：调度器挂在 server layout 的模块顶层，**服务器收到第一个请求后**才开始 60 秒扫描；
  纯后台无人访问的部署应换成独立进程或 instrumentation 的 Node-only 入口。

## 11. 长会话上下文压缩（2026-11-13）

多轮 Agent 迟早会撑爆模型窗口。`lib/agent/compact.ts` 在每一次请求前按**完整 user 回合**裁剪：

- 预算是 `contextWindow × 0.62`；超过才动手；
- 从最早的 user 回合开始丢，一次丢一整个回合（user → assistant/tool → 下一个 user），
  保证不会留下没有 `assistant.tool_calls` 的孤儿 `tool` 消息；
- 永远保留 system 与最后一轮；
- 裁剪发生后在 system 末尾追加一行「部分早期回合已移除」的说明。

`study/compact-check.ts` 用 Node 24 的类型剥离直接跑纯函数：
15,580 → 11,705 tokens（预算 12,000），25 → 19 条消息，`orphan=false`、最后一轮保留、
提示已注入。

  标题本体不再带方括号；服务端与浏览器 runner 生成的报告都适用。

  `deepseek-v4.1-flash` 不再出现。截图：`221-model-filter.png`。

  嵌套 `<button>` 会被浏览器重排导致点击落到「打开议题」。

  API 返回 `ok=true, chars=28`。文件选择器接受 `.pdf`。
