# Aether：ChatGPT × Linear 优化总表

> 审计时间：2026-11-13。基于实际源码、现有页面与官方产品资料，而非仅依据 README。范围是当前本地优先、BYOM 的 Aether；不复制闭源实现，不把不支持的 Provider 能力包装成已支持。
>
> 参考：[ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)（项目文件/指令/记忆/共享/分支）、[Linear 文档](https://linear.app/docs) 与项目内 clean-room 采样。官方能力因账号、模型和端点而异。

## 现状与原则

- 已有：议题列表/看板/详情、项目/周期/路线图、命令面板、键盘操作、账号与 JSON 持久化、BYOM 多模型、流式回复、工具审批、记忆/知识库、工作流和桌面壳。
- 基线：`tsc --noEmit` 与 `next build` 通过；但这只证明可构建，不等于每条交互已验收。
- 先做数据不丢、操作可撤销、状态可恢复；再做工作流效率；最后做模型与平台能力。

## P0：数据、恢复与操作正确性

| 项目 | 审计发现 | 完成判据 |
|---|---|---|
| 按会话保存草稿 | 输入与附件是面板单份 state，切会话/刷新会丢或串 | 草稿按会话隔离，刷新恢复，发送后清除 |
| 附件编辑 | 待发送附件不能逐个移除 | 移除单个附件，保留其余内容 |
| 指定轮次编辑 | 点击旧消息的编辑实际回退最后一轮 | 以所选 user turn 为边界，后续上下文不再误发给模型 |
| 真正重新生成 | Retry 在原历史后追加同一问题，旧回答仍在上下文 | 截去最后回答再调用，避免重复问题与旧指令 |
| 会话分支 | 无保留原对话的探索路径 | 从指定轮次创建带历史前缀的新会话，可返回源会话 |
| 中断恢复 | 刷新抹掉 running/waiting，控制器和审批仅存内存 | 明确显示中断，可重试/续跑；不冒充未断开的执行 |
| 会话保存一致性 | 40 个标题与最多 16 份正文不一致 | 保留、淘汰、归档有同一规则；正文和元数据同步 |
| 上下文计量 | 累计账单 token 与本轮上下文占比混用 | 估算本轮请求，标明估算；usage 单独展示 |
| 同步冲突 | 409 后刷新可能丢本地未落库修改，用户不知情 | 不静默覆盖；导出/保留本地快照并提示，支持重试 |
| 全局撤销 | 删除、批量修改、看板拖拽不可逆 | Toast 撤销 + Ctrl/Cmd-Z；不误抢编辑器原生撤销 |
| 议题深链历史 | 仅 team 页读取 query，打开时写入 id，浏览器返回不恢复 | key/id 均可恢复；打开/关闭形成正确历史 |
| 服务端原子更新 | 知识/记忆/工作流读取在锁外，可能丢更新 | 同账号同文件的完整 read-modify-write 串行 |
| 数据导入与存储错误 | 部分配额/网络错误被静默吞掉 | 可感知错误、可导出恢复、测试覆盖关键路径 |
| 基础自动化 | 当前无统一 test/e2e 命令 | 关键纯函数与浏览器流程可重复执行 |

## P1：ChatGPT 对标

| 方向 | 要做的事 |
|---|---|
| 项目空间 | 项目内发起对话；项目指令；关联议题/文件/知识；项目级记忆边界；把已有会话移入项目 |
| 会话管理 | 分支、归档、置顶、重命名、全文搜索、批量导出、删除确认、按时间分组 |
| 回复控制 | 指定回答重新生成；模型切换只影响后续；停止、排队、编辑原文；反馈入口 |
| 内容与代码 | 完整 Markdown、代码块复制、表格横向滚动、链接安全、引用定位、网页来源可追溯 |
| 输入体验 | 自动增高、草稿、粘贴图片、拖拽文件、附件移除、错误恢复、语音输入（浏览器支持时） |
| 文档产物 | 将回答变成可编辑文档/笔记；预览、版本和 Markdown 下载；后续扩展代码工作区 |
| 个人上下文 | 记忆作用域、显式引用、关闭记忆的对话、项目指令与全局指令分层 |
| 执行透明度 | 全局活动任务、跨会话状态、失败原因、工具参数和结果关联、可恢复审批 |
| 定时任务 | 通知与完成入口、任务暂停/恢复、错过调度说明、失败重试与最大重试 |
| 多媒体与工具 | PDF/Office/CSV 可用性、图像能力检测、联网搜索与引用；语音和生成能力依 Provider 适配 |
| 分享协作 | 只读会话链接/导出分享、项目权限、协作者可见范围；默认不公开私密内容 |

| 撤销与删除 | 全局撤销；归档/恢复；删除时关联和子议题的明确行为 |

| 看板 | 键盘移动、可访问的拖放替代、列管理、撤销、长列性能 |
| 搜索与命令 | 内容高亮、筛选语法、最近访问、命令分级、上下文动作与快捷键一致性 |
| 移动与桌面 | 移动端历史/返回、触控目标、离线提示；桌面菜单/托盘/更新与深链 |
| 设计品质 | 语义 token、键盘焦点、Reduced Motion、对比度、国际化、真实空/加载/错误态 |

## P2：规模、生态与差异化

1. 实体级 mutation、事件日志和离线队列，替代整份 JSON 快照反复同步。
2. 多窗口/多设备实时更新与冲突解决；可验证的协作权限，而不是仅有多账号。
3. 混合检索（全文 + embedding + 引用）与分块索引；大量知识的增量更新。
4. 统一 connector 接口，接 GitHub、Slack、Drive 等；每个外部写操作仍有预览/审批。
5. Canvas 式文档与代码并排工作区、diff、版本回退和交付文件。
6. 使用统计、Provider 配额/成本、延迟与失败率；从真实 usage 计量，不伪造数字。
7. 可配置的 Agent 权限、并行任务、项目模板、工作流触发事件和运行账本。
8. 桌面自动更新、跨平台签名/打包、崩溃恢复、可迁移数据与备份验证。
9. 无障碍自动扫描、E2E/组件测试、性能预算、错误监控、版本迁移测试。

## 执行顺序

`NEXT.md` 是按阶段归并的可执行队列；`scripts/improve.mjs` 负责显示进度、执行验证和通过同一个持久会话续跑。每阶段提交的不是一个按钮，而是“源码 + 类型/构建 + 可重复的操作验收 + 记录”。
