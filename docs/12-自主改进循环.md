# 12 · 自主改进循环（Autopilot）

Aether 的持续改进由 `scripts/autopilot.mjs` 驱动。它不依赖外部服务，不需要数据库，重启后能从上次的位置继续。

## 一轮是什么

```
读队列 → 交给 headless agent → 跑门禁 → 本地提交 →（可选）推送
```

1. **读队列**：只取 `NEXT.md` 的 `## 待办` 第一条。`## 阻塞（需要外部资产）` 不参与轮转。
2. **交给 agent**：把该条、最近门禁结果、仓库规则写成一段 prompt，用一个持久会话 id 启动 `dsh headless`。同一个会话让 agent 记得上一轮做过什么，不必每轮重新读全仓。
3. **跑门禁**：`typecheck`（`tsc --noEmit`）→ `regression`（`node scripts/regression.mjs`）→ 可选 `build` / `i18n`。第一条失败就停，后面的不跑。
4. **提交**：门禁全绿才 `git add -A && git commit`。提交信息取当前待办前 64 字。`--push` 才会推送。
5. **记账**：`.improve/autopilot.json` 记录轮次、历史、上次门禁；`.improve/autopilot.log` 是逐行日志。

## 命令

```bash
node scripts/autopilot.mjs --status          # 队列、候选、门禁、git 是否干净
node scripts/autopilot.mjs --once            # 跑一轮（默认门禁 typecheck+regression）
node scripts/autopilot.mjs --rounds 3        # 连跑三轮
node scripts/autopilot.mjs --until-dry       # 跑到队列为空（每轮最多 45 分钟）
node scripts/autopilot.mjs --check           # 只跑门禁，不动代码（= PR 门禁）
node scripts/autopilot.mjs --check --stash-on-fail   # 门禁失败时把工作树 stash 掉
node scripts/autopilot.mjs --seed            # 把差距清单的候选搬 3 条进 NEXT.md
node scripts/autopilot.mjs --dry-run         # 打印这一轮会用到的 prompt
node scripts/autopilot.mjs --gates typecheck,regression,build,i18n
node scripts/autopilot.mjs --push            # 门禁通过并提交后推送
node scripts/autopilot.mjs --revert-on-fail  # 门禁失败时把本轮改动 stash
node scripts/autopilot.mjs --no-agent        # 只跑门禁（调试驱动本身）
node scripts/autopilot.mjs --resume          # 沿用 .improve 里记录的会话（默认每轮新会话）
node scripts/autopilot.mjs --agent-cmd 'claude -p "$(cat {{promptFile}})"'   # 换一个 one-shot CLI
node scripts/autopilot.mjs --no-probe        # 跳过开跑前的探活
node scripts/autopilot.mjs --wait 180        # 探活失败时最多等 180 分钟（默认 0 = 立即退出）
node scripts/autopilot.mjs --retries 3 --retry-delay 60   # 传输错误重试次数与间隔
node scripts/autopilot.mjs --agent-cmd "scripts\agent-claude.cmd"   # 换 Claude Code 当 agent
node scripts/autopilot.mjs --allow-empty-rounds   # 允许「跑完但没改代码」的轮次
```

npm 别名：

```bash
npm run autopilot           # --once
npm run autopilot:status
npm run autopilot:check
npm run autopilot:until-dry
```

## 三道诚实性护栏

1. **探活（默认开）**：第 1 轮之前先让 agent 回一个 `OK`。没有输出就**不进入轮次**，直接退出码 4 并打印原因 —— 一个不说话的 agent 会让每一轮都「成功」却什么都没改。
2. **空轮检测**：agent 结束后对比 `git status --porcelain`，与开跑前一致即判定「没进展」，退出码 5 并保留现场（`--allow-empty-rounds` 可关）。
3. **门禁优先**：门禁不过不提交；`--revert-on-fail` 把本轮改动 `git stash` 掉，工作树保持绿色。

## headless agent 的凭据（重要）

`dsh headless` 走的是 **环境变量 / `.env`** 取模型 key，**不读 GUI 里保存的登录态**：

- 取值顺序：启动环境 → `<cwd>/.env` → `$DSH_HOME/.env`；
- 模型端点由 profile 决定：本机的 headless profile 指向 `http://127.0.0.1:3425/v1`（magpie 网关），**网关没起就是 `TRANSPORT: Connection error`**；
- `--session-id <id>` 只能**沿用已存在**的会话（同一 cwd），随便编一个会直接报 `session ... does not exist`；
- 默认每轮一个新会话，id 从 `--json` 的第 1 个 `session` 事件里取，存在 `.improve/autopilot.json` 的 `sessionId`，需要延续时加 `--resume`。

网关没起时有两个办法：

```bash
# 1) 让循环等它回来（每 30 秒探一次，最多 180 分钟）
node scripts/autopilot.mjs --until-dry --push --wait 180

# 2) 换一个 agent：仓库自带 Claude Code 适配器
node scripts/autopilot.mjs --until-dry --push --agent-cmd "scripts\agent-claude.cmd"
```

`agent-claude.ps1` 从 `AUTOPILOT_PROMPT_FILE` 读整段 prompt 再喂给 `claude -p`，所以多行中文不会经过 cmd.exe 的引号；适配器只负责转发退出码，门禁、提交、推送仍由驱动器管。

## CI 接线：`autopilot --check` 就是 PR 门禁

`.github/workflows/ci.yml` 有两个 job，分工不重叠：

| job | 跑什么 | 作用 |
| --- | --- | --- |
| `gate` | `node scripts/autopilot.mjs --check --gates typecheck,regression --stash-on-fail` | PR 门禁：本地循环用的同一份门禁代码 |
| `build` | lint / i18n / build / 两条 smoke | 门禁之外的一切 |

`--check` 一次跑完会留下四样证据，CI 用 `actions/upload-artifact` 全部上传（`gate-report`，保留 14 天）：

| 产物 | 内容 |
| --- | --- |
| `.improve/gate-report.md` | 人读的汇总：时间、分支与提交、每道门的 pass/FAIL/not run、失败门的末 12 行、stash 结论；同时写进 `$GITHUB_STEP_SUMMARY` |
| `.improve/gate-report.json` | 同一份报告的结构化版本（`version: 1`），给脚本与后续自动化读 |
| `.improve/logs/gate-<name>.log` | 每道门的**完整**输出（不是末 12 行），失败复盘用 |
| `.improve/autopilot.log` | 逐行运行日志 |

规则与取舍：

- **门禁失败 = 退出码 1**，未知门名（`--gates typo`）也是失败（退出码 2 的结果被算成 fail），不会被静默跳过。
- **`skipped` 不算 pass**：门禁在第一条失败处停下，后面的门在报告里写 `not run`，汇总仍是失败。
- **失败自动 stash**：`--stash-on-fail` 在「门禁失败 **且** 工作树非空」时执行 `git stash push -u -m "autopilot gate failed: <门名> @ <时间>"`，让下一次重跑从干净树开始；成功时报告记下 `stash@{0} (<短哈希>)`，跳过时记原因（未开启 / 门禁通过 / 工作树本来就干净）。CI 里 checkout 通常是干净的，所以多数时候结论是 `not needed (working tree was clean)` —— 这条机制主要服务于本地连续重跑。
- **stash 不掩盖退出码**：stash 成功或失败都不改变门禁的失败结论；stash 自己失败时报告写 `stash failed, the tree is left as it was`。
- **纯逻辑在 `lib/ci/gate-report.ts`**：门名归一化、日志裁剪、`skipped` 判定、stash 策略、报告渲染、退出码，全部是无副作用的函数，`scripts/regression.mjs` 用 1 组 56 条断言覆盖。
- **分支保护**：把 `ci / gate` 设为 required check，PR 才会真的被拦住；workflow 本身不改仓库设置。

本地复现 CI 那一步：

```bash
node scripts/autopilot.mjs --check --gates typecheck,regression --stash-on-fail
echo $?                      # 0 = 可以合并；1 = 看 .improve/gate-report.md
git stash list               # 失败时这里会多一条 autopilot gate failed: …
```

## 状态文件

| 文件 | 作用 | 是否入库 |
| --- | --- | --- |
| `.improve/autopilot.json` | 轮次、历史、上次门禁结果、会话 id | 否（`.improve/` 已忽略） |
| `.improve/autopilot.log` | 逐行日志，出事第一现场 | 否 |
| `.improve/round-prompt.txt` | 本轮完整 prompt，便于复盘 agent 收到了什么 | 否 |
| `.improve/autopilot.lock` | 进程锁，防止两个循环同时改一个工作树 | 否 |
| `.improve/gate-report.md` / `.json` | 最近一次门禁报告（人读 / 机读），CI 作为 artifact 上传 | 否 |
| `.improve/logs/gate-<name>.log` | 每道门的完整输出 | 否 |

## 无人值守

```powershell
# 后台跑，日志进 .improve/autopilot.out.log
Start-Process -FilePath node -ArgumentList 'scripts/autopilot.mjs','--until-dry','--push' `
  -WorkingDirectory 'E:\fork\3' -RedirectStandardOutput '.improve\autopilot.out.log' `
  -RedirectStandardError '.improve\autopilot.err.log' -WindowStyle Hidden
```

停止：`Get-Process node | Where-Object { $_.StartTime -gt (Get-Date).AddHours(-6) }` 找到进程后结束，或删掉锁文件让下一轮接管（脚本会检测 pid 是否还活着）。

## 安全边界

- **不碰用户数据**：`.data/`、`.env.local` 在 `.gitignore` 里，循环不读不写；prompt 里也明确禁止。
- **失败不改仓库状态**：门禁失败只记录，除非显式 `--revert-on-fail`，否则改动留在工作树里等人看。
- **一次一条**：一轮只推进一条待办，避免「顺手重构」把 diff 撑大、门禁失真。
- **可复现**：每轮 prompt 落盘，门禁命令固定；同一份代码跑两次门禁结果一致。
- **不自动推送**：默认只提交到本地，`--push` 是显式动作。

## 给 agent 的固定要求（写在 prompt 里）

1. 先看源码确认现状，不重复已实现的能力。
2. 纯逻辑进可测试模块，补 `scripts/regression.mjs` 用例；界面改动在真实 dev 上验收。
3. 不破坏 BYOM、本地数据与既有能力。
4. 每轮结束前 `tsc --noEmit` 与 `regression` 必须过。
5. 不执行 `git commit` / `push`，由驱动器统一提交。
6. 完成后用 `node scripts/next.mjs --done "<原文>"` 勾选并记录验证方式。
7. 遇到外部资产阻塞，拆成可验证的子任务继续，不空转。

## 已知限制

- `dsh headless` 需要本机已登录的模型配置；CI 里不跑 agent 轮次，只跑 `--check`（纯门禁），所以不需要模型凭据。
- 门禁里的 `build` 需要 1–3 分钟，所以默认只跑 `typecheck,regression`（PR 门禁也是这两条），提交前手动补一次 `npm run build`。
- `--stash-on-fail` 只对**未提交**的改动生效：已提交的红代码要靠 revert，stash 帮不上。
- 循环不会自己发现新需求：燃料来自 `NEXT.md` 和 `docs/11-产品差距清单.md`，两者都由人维护。
