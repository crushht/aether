# 14 · Agent 成熟度路线图（v0.5 队列）

这份文件回答一个问题：**Aether 从「能跑通的 agent 工作台」到「成熟的 agent 产品」还差哪几步。**

`docs/11` 是「对标差距」（Linear 有什么、ChatGPT 有什么），这份是「成熟度」（同一件事做到了什么程度）。
两者互补：对标看**有没有**，成熟度看**靠不靠得住**。

用法与 `docs/13` 相同：`autopilot --seed` 认这里的 `- [ ]`，做完改 `- [x]`，否则会被重新搬进队列。

---

## 一、成熟度评级

评级：**A** 可交付 · **B** 可用但会露怯 · **C** 只有骨架

| 维度 | 现在的证据 | 评级 | 成熟意味着什么 |
| --- | --- | --- | --- |
| 工具调用 | 22 个工具、只读判定、审批白名单、结果卡片 | ◐ B | **每次调用有耗时与尝试次数；失败能原地重试而不是重跑整轮** |
| 上下文管理 | `compactMessages` 裁掉最早整轮，`ContextMeter` 显示占比 | ◐ B | **说清楚这一轮裁了什么、为什么；被裁的内容可回看** |
| 多步执行 | 步数上限、步骤折叠、计划视图、中断恢复 | ● A | 步数耗尽时给出「继续」而不是「重问一次」 |
| 记忆与知识 | 知识库、混合检索、remember/recall、`id#chunk` 引用 | ● A | 记忆条目的可见与编辑入口（已有 recall 面板） |
| 可溯源 | `citations.ts`：网页/知识命中变成 chip | ● A | — |
| 工具失败处理 | 模型被告知「被拒绝别重试」；没有重试语义 | ○ C | **失败是状态，不是结局：一键重试、退避、台账** |
| 会话附件 | 文本内联进 prompt，图片进 image_url | ◐ B | 大文件走工具按需读，别把 token 一次性烧掉 |
| 模型接入 | BYOM、多 provider、路由、预设、保存校验 | ● A | 参数档位（精确/平衡/发散）落在 provider 上 |
| 工作流 | 定时/事件、台账、取消、导出、失败一键重试 | ◐ B | 失败自动退避重试，每次尝试进台账 |
| 议题体验 | 列表/看板/抽屉/依赖/周期/保存视图/查询语法 | ● A | 依赖关系可视化、WIP 上限 |
| 通知 | 收件箱、偏好、免打扰、摘要、归档清理 | ◐ B | 稍后处理（snooze）、项目 × 类型矩阵 |
| 权限 | owner/member 两档，最后一位 owner 保护 | ◐ B | 项目级可见/可编辑两档 |
| 工程 | 29 组回归、108 个 e2e、门禁进 CI | ● A | e2e 冒烟进 CI，依赖体检报告 |

**结论**：产品面（Linear 对标）已经到 A 的大半，agent 面（ChatGPT 对标）卡在**可观测性与失败处理**这两件事上——
它现在「会做事」，但做完之后**看不出花了多久、失败了几次、为什么失败、能不能只重来那一步**。这就是 v0.5 的主线。

## 二、队列（按顺序，一条一轮）

### P1 · agent 成熟度主线

- [ ] P1 工具调用可观测性与单次重试：每次工具调用的耗时与尝试次数进 transcript（`2.4s · 第 2 次`），失败行给「重试这次调用」，复用同一 args 重跑
      —— 纯逻辑 `lib/agent/tool-retry.ts`（可重试判定、日志补丁、会话消息对账、时长格式化）+ 回归 + `scripts/e2e-tool-retry.mjs`
- [ ] P1 上下文预算解释器：把 `compactMessages` 的裁剪结果变成可读报告（裁掉几轮、多少 token、从哪条开始保留），
      运行中写一条 `note` 行，输入框上方的 ContextMeter 可展开看明细 —— 纯逻辑 `compactionReport()` + 回归
- [ ] P2 模型参数预设：温度/步数做成「精确 / 平衡 / 发散」三档（0.1/8、0.3/12、0.7/20），落在 provider 上，设置页一键切换
      —— 纯逻辑 `lib/agent/model-presets.ts` + 回归 + 设置页
- [ ] P2 工作流退避重试：失败后 1 / 5 / 15 分钟自动重试，每次尝试写进运行台账（第几次、退出原因）
      —— 纯逻辑 `lib/agent/workflow-retry.ts` + 调度器接线 + 回归

### P1 · Linear 对标补齐

- [ ] P1 依赖视图：把 `blocks / blocked_by` 画成 SVG 分层有向图（按拓扑层级排布、箭头、环检测降级为列表），点节点打开抽屉
      —— 纯逻辑 `lib/dependency-graph.ts` + 回归 + 议题抽屉「依赖」页签
- [ ] P2 收件箱稍后处理：通知菜单加「1 小时 / 明天 / 下周」，到期前不出现在未读、不计入角标
      —— 纯逻辑 `lib/notification-snooze.ts` + 回归 + e2e
- [ ] P2 看板 WIP 上限：列头显示「3 / 5」，超限变红并给出说明；上限存视图偏好（per account）
      —— 纯逻辑 `lib/wip-limits.ts` + 回归 + 看板列头
- [ ] P2 周期吞吐表：按周统计完成点数与平均周期，与燃尽图同页 —— 纯逻辑 `lib/cycle-throughput.ts` + 回归

### P2 · 权限与数据

- [ ] P2 项目级权限：成员在项目上的可见/可编辑两档，服务端校验，回归覆盖越权路径
- [ ] P2 通知偏好矩阵：项目 × 类型的二维开关，替代一维列表 —— 纯逻辑 + 设置页
- [ ] P3 审计流导出 CSV：列固定、UTF-8 BOM（Excel 直接打开）

### P3 · 工程

- [ ] P3 e2e 冒烟进 CI：挑 6 个最稳的 `e2e-*.mjs` 在 CI 里跑（dev server + CDP），失败上传截图
- [ ] P3 依赖体检：`npm outdated` 生成报告写 `.improve/deps.md`，不自动升级
- [ ] P3 快捷键帮助补全：`?` 面板列出全部键位（含 `G` 前缀序列），与 `shortcuts.tsx` 同源

## 三、一轮的验收标准（不可跳）

1. 纯逻辑进 `lib/**`，不依赖 React，不读 DOM。
2. `scripts/regression.mjs` 增一组断言，覆盖边界（空值、坏形状、上限、顺序）。
3. 界面改动在真实 dev（`AUTH_DISABLED=1`，端口 4321）上跑一个 `scripts/e2e-*.mjs`，断言具体属性而不是「看起来对」。
4. 门禁：`npx tsc --noEmit` + `node scripts/regression.mjs`；提交前 `npm run build` + `npm run i18n`。
5. `NEXT.md` 勾掉该条并在「已完成」顶部记一行（含验证命令与结论）。
6. `docs/11` 的对标矩阵按当轮结果改评级 —— 只改真的变了的行。

## 四、不做什么（保持边界）

- 不内置模型：所有推理只走用户配置的 provider。
- 不做代码执行沙箱（需要独立的进程/容器决策，不是一轮能交付的）。
- 不为了「看起来有」而加没有验收方式的条目：写不出断言的，不进队列。
